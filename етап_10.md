# Етап 9 — Продакшн на Hetzner (IPv6) + Cloudflare Tunnel

Чудовий вибір інфраструктури. Під IPv6-only Hetzner + Cloudflare найкраща архітектура — **Cloudflare Tunnel**: origin не слухає жодного публічного порту, TLS термінується на edge Cloudflare, реальний IP клієнта приходить у `CF-Connecting-IP`, а IPv6-only сервер взагалі не потребує вхідного IPv4. Нижче — адаптований скрипт.

Запуск (з `~/projects`):

```
nano stage9_hetzner_cloudflare.sh
chmod +x stage9_hetzner_cloudflare.sh && ./stage9_hetzner_cloudflare.sh
```

# ── 02. Cloudflare Real-IP middleware ──────────────────────────────────────
cat > core/middleware.py << 'EOF'
"""Cloudflare-aware middleware.

Cloudflare Tunnel гарантує, що запити потрапляють на origin ВИКЛЮЧНО через
cloudflared (порт не публікується назовні), тому підробка CF-Connecting-IP
із зовнішньої мережі неможлива. Це безпечніше за класичний proxy-варіант.
"""
from django.conf import settings


class CloudflareRealIPMiddleware:
    """Підставляє реальний IP клієнта з CF-Connecting-IP у REMOTE_ADDR.

    Потрібен для коректних логів, rate-limiting та аналітики. Працює лише
    коли запит пройшов через Cloudflare (наявний заголовок CF-Connecting-IP).
    """

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        cf_ip = request.META.get("HTTP_CF_CONNECTING_IP")
        if cf_ip:
            request.META["REMOTE_ADDR"] = cf_ip
        return self.get_response(request)
EOF

Архітектура:
  Клієнт ──TLS──▶ Cloudflare Edge ──Tunnel──▶ cloudflared ──▶ gunicorn:8000

  - Origin НЕ слухає публічних портів (тільки внутрішня docker-мережа)
  - Реальний IP клієнта — у CF-Connecting-IP (middleware)

# TUYYO.CLUB — nginx на Hetzner (IPv6) за Cloudflare (режим Full Strict).
# Використовувати ЗАМІСТЬ Cloudflare Tunnel, якщо потрібен класичний proxy.
# Cloudflare Origin Certificate (15 років) — з панелі Cloudflare → SSL/TLS → Origin Server.
upstream tuyyo_web {
    server web:8000;
}

server {
    # IPv6 + IPv4 (якщо є). Hetzner IPv6-only — лишається лише [::].
    listen [::]:80;
    listen 80;
    server_name tuyyo.club www.tuyyo.club;
    return 301 https://tuyyo.club$request_uri;
}

server {
    listen [::]:443 ssl http2;
    listen 443 ssl http2;
    server_name tuyyo.club;

    # Cloudflare Origin Certificate (довіряє лише Cloudflare edge)
    ssl_certificate     /etc/nginx/ssl/tuyyo.club.pem;
    ssl_certificate_key /etc/nginx/ssl/tuyyo.club.key;
    ssl_protocols       TLSv1.2 TLSv1.3;

    client_max_body_size 20m;
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;

    # Реальний IP клієнта — з Cloudflare
    set_real_ip_from 2400:cb00::/32;
    set_real_ip_from 2606:4700::/32;
    set_real_ip_from 2803:f800::/32;
    set_real_ip_from 2405:b500::/32;
    set_real_ip_from 2405:8100::/32;
    set_real_ip_from 2a06:98c0::/29;
    set_real_ip_from 2c0f:f248::/32;
    real_ip_header CF-Connecting-IP;

    location /static/ {
        proxy_pass http://tuyyo_web;
        proxy_set_header Host $host;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location / {
        proxy_pass http://tuyyo_web;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_read_timeout 60s;
    }
}
EOF

cat > deploy/hetzner-firewall.sh << 'EOF'
#!/usr/bin/env bash
# Hetzner Cloud Firewall через hcloud CLI (альтернатива UFW).
# Закриває всі вхідні порти, лишає SSH + ICMPv6. Порти 80/443 НЕ відкриваємо —
# увесь веб-трафік іде через Cloudflare Tunnel (outbound-з'єднання cloudflared).
set -euo pipefail
SERVER="${1:-tuyyo}"

hcloud firewall create --name tuyyo-fw \
  --rules-file /dev/stdin <<'JSON'
[
  {"direction":"in","protocol":"tcp","port":"22","source_ips":["::/0","0.0.0.0/0"]},
  {"direction":"in","protocol":"icmp","source_ips":["::/0","0.0.0.0/0"]}
]
JSON
hcloud firewall apply-to-resource tuyyo-fw --type server --server "$SERVER"
echo "✅ Firewall застосовано: відкрито лише SSH(22) + ICMP. Веб — через Cloudflare Tunnel."
EOF

# TUYYO.CLUB — Деплой на Hetzner Cloud (IPv6) + Cloudflare

1. Cloudflare Zero Trust → **Networks → Tunnels → Create a tunnel** → Cloudflared.
2. Назвіть tunnel (напр. `tuyyo`), скопіюйте **Token**.

4. Додайте ще один hostname для `www.tuyyo.club` → `http://web:8000`.
5. DNS-записи (CNAME на `<tunnel-id>.cfargotunnel.com`) створяться автоматично.

У Cloudflare DNS переконайтеся, що записи **proxied (orange cloud)**.
SSL/TLS → режим **Full** або **Full (Strict)**. Увімкніть **Always Use HTTPS**.

curl http://localhost:8000/healthz/  # через тимчасово розкоментований port, або:

# ── 16. ADR-0008 ───────────────────────────────────────────────────────────

cat > docs/adr/0008-hetzner-ipv6-cloudflare-tunnel.md << 'EOF'

# ADR-0008: Hetzner (IPv6) + Cloudflare Tunnel замість класичного proxy

**Статус:** ухвалено · **Дата:** 2026-08-01

Сервер на Hetzner Cloud — IPv6-only. Класичний варіант (nginx/Caddy на [::]:443

+ Cloudflare proxy) потребує відкритих портів, сертифікатів і захисту від
  обходу edge (firewall на Cloudflare IP-діапазони).

**Cloudflare Tunnel** елегантніший:

- `cloudflared` робить outbound-з'єднання до Cloudflare edge — вхідних портів
  немає взагалі, IPv4 не потрібен.
- TLS термінується на Cloudflare; на origin — простий gunicorn + WhiteNoise.
- Реальний IP клієнта приходить у `CF-Connecting-IP`; оскільки порт закритий,
  підробка цього заголовка ззовні неможлива → middleware без перевірки діапазонів
  є безпечним (на відміну від відкритого proxy).
- `SECURE_PROXY_SSL_HEADER = X-Forwarded-Proto`, `SECURE_SSL_REDIRECT = False`
  (редирект робить Cloudflare "Always Use HTTPS").

nginx/Caddy-конфіги збережено в `deploy/` як fallback для Full (Strict) режиму.
EOF

## Ключові рішення під вашу інфраструктуру

- **Cloudflare Tunnel як основний шлях** — origin не слухає публічних портів, IPv4 не потрібен (ідеально для IPv6-only Hetzner), TLS на edge, реальний IP у `CF-Connecting-IP`.
